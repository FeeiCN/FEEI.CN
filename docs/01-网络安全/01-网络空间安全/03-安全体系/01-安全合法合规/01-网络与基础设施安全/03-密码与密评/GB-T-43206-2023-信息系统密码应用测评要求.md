# GB/T 43206-2023 信息系统密码应用测评要求

密评需要验证密码机制在真实系统中是否正确、有效地工作，并与适用要求相符。[官方标准信息](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=EE1B34C97A17C6F13FA9A9D891C144C2)列明：2023年9月7日发布，2024年4月1日实施。建设基线参见[GB/T 39786](./GB-T-39786-2021-信息系统密码应用基本要求.md)。

本页给出企业准备与复核方法，不自行设定测评评分、通过阈值或统一密码参数；具体测评单元、判定及风险分析以正式全文和适用规则为准。

## 先核对测评对象与实际实现

输入应包含系统边界、保护级别、密码应用方案、实际产品和版本、算法协议、证书密钥、调用关系、管理制度及运行记录。需要方案评估、上线前评估和运行期评估的场景，分别依[密评管理办法](./商用密码应用安全性评估管理办法.md)判断，不能用一份方案审查代替生产有效性验证。

测评前双向对账：从方案找实际调用，从实际流量、配置、SDK和密码设备找方案。对没有接入生产的产品、无法提供证据的机制和范围外组件，分别记录，不能混入“已覆盖”数量。

## 设计、配置和效果分别验证

| 验证层次 | 要检查什么 | 证据示例 |
| --- | --- | --- |
| 适用性与来源 | 技术、产品、服务是否符合本项目适用要求 | 标准条款、证书及精确型号版本 |
| 设计 | 保护对象和目标是否完整，方案是否覆盖实际边界 | 数据流、身份和密钥关系 |
| 配置 | 实际协议、证书、权限和参数是否对应方案 | 设备与应用配置、调用端设置 |
| 运行 | 机制是否真实被调用，失败时如何处理 | 日志、流量、返回结果和异常行为 |
| 管理 | 密钥、人员、变更和审计是否受控 | 授权、操作、轮换与独立复核记录 |

访谈和方案材料可以解释设计，但不能单独证明生产调用已经生效。反过来，一次正常连接成功，也不能证明证书验证和异常分支正确。

## 示例：客户端未验证服务器身份

**假设。** 应用与服务间有加密流量，但客户端关闭了证书校验。正常流量抓包显示密文，验收因此误写“通信安全通过”。

**测试。** 在授权测试环境替换为不受信任、过期或身份不匹配的测试证书，验证客户端是否拒绝连接；再确认生产发布配置与被测版本一致。测试不涉及窃取真实会话或生产密钥。

**结果。** 若错误身份仍被接受，应描述具体调用方、配置、触发条件和受影响链路。整改校验配置及发布控制后，对原失败场景复测，不能只重新截取一份正常握手画面。

这个案例说明加密与身份鉴别需分别验证，不能据此概括所有密码测评项目的结论。

## 密钥和备用链路的反向检查

对已声明的密钥隔离，验证业务管理员能否额外取得导出权限；对轮换，验证新旧密钥、历史数据和缓存的一致性；对备份恢复，验证授权和密码保护是否持续存在。密码服务失败时，应观察应用是否跳过校验、退回明文或调用未纳管的备用实现。

抽样应记录总体、样本和限制。存在等效方案或不适用项时保留技术事实与依据，不以“暂时测不了”替代不适用论证。

## 结论、整改和持续有效性

每条发现关联：`测评项 → 对象 → 原始证据 → 判定依据 → 风险影响 → 整改 → 复测`。正式结论由相应测评要求确定；企业不能凭内部风险接受将不符合项标为符合。

方案、产品固件、密钥体系、协议或部署边界变化后，重新核对原报告范围并判断是否需追加验证或评估。运行期证据应能表明被测控制仍在使用。
