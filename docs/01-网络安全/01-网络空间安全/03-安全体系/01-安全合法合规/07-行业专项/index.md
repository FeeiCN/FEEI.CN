# 行业专项

先完成通用网络、数据和个人信息判断，再确认本行业是否增加了特定对象、处理限制、评估或报告要求。行业身份不应成为重复建设整套安全流程的理由。

## 按实际场景选择

| 当前业务 | 优先阅读 | 重点问题 |
| --- | --- | --- |
| 汽车制造、零部件软件、经销维修或出行数据 | [汽车数据安全管理若干规定](./汽车数据安全管理若干规定.md) | 车端处理、敏感信息、重要数据及年度报告 |
| 银行、支付或其他金融业务 | [支付与金融安全](../04-支付与金融安全/index.md) | 牌照主体、行业数据和事件规则 |
| App、内容、算法或AI服务 | [平台App与AI](../05-平台App与AI/index.md) | 产品能力、用户群和专项程序 |
| 境外经营或海外客户服务 | [海外业务安全合规](../06-海外业务安全合规/index.md) | 当地准入、数据、系统与报告 |

本目录当前只对汽车数据设置独立明细页。未列出的行业不代表没有专项规则，实际进入业务前仍需核对主管机关和产品形态。

## 汽车场景的组合阅读

车机采集位置、影像或人脸时，先核对汽车数据专项条件，再衔接[个人信息保护](../02-数据与隐私安全/index.md)；境外研发查询、日志同步和云服务涉及跨境时，继续进入[数据跨境](../03-数据跨境/index.md)。车端、App、后台和受托方应在同一张数据流图中。

## 验收结果应具体到业务对象

建议为每项专项义务记录车型或服务、数据对象、控制位置、责任方和证据。以车辆或真实接口验证默认设置、采集状态、传输、删除及报告材料，而不只核对隐私政策。

新增专题优先说明相对通用制度增加了什么。已有支付、平台和海外内容通过链接复用，不重复搬入本目录。
