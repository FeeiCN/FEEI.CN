# 安全合法合规

**安全负责人看法律法规，核心任务是把条文要求转化为组织可执行、可审计、可追责的安全治理动作。** 这套法规体系最终要回答的是：公司属于什么主体，保护哪些对象，哪些业务会触发监管要求，平时要落哪些控制，发生事件后如何报告和整改。

[法规关系](#legal-map) · [公布与施行时间](#legal-dates) · [处罚与其他法律后果](#legal-liability) · [企业治理落地](#implementation)

本页围绕本目录收录的 **41 份法律、法规、规章及规范性文件**建立索引，按截至 2026 年 9 月 21 日可核验的正式文本整理；不覆盖中国大陆全部法律体系。文件名称链接到本站解读，日期和责任条款链接到官方原文或官方转载。具体案件还需结合行为发生时间、适用主体、构成要件和裁量规则，由法务核定适用依据。

## 法规关系与适用顺序 {#legal-map}

### 先看效力层级，再看业务适用范围

在本目录涉及的国家层面规范中，法律的效力高于行政法规，行政法规的效力高于部门规章。依据是《立法法》[第 99 条][src-legislation]。行政规范性文件在法定权限内细化执行要求；《行政处罚法》[第 16 条][src-administrative-penalty]明确，法律、法规、规章以外的其他规范性文件不得设定行政处罚。

| 层级 | 本目录中的代表文件 | 阅读时需要确认的关系 |
| --- | --- | --- |
| 法律 | 网络安全法、数据安全法、个人信息保护法、国家安全法、密码法、电子签名法、反电信网络诈骗法 | 确定基本制度、权利义务和责任；这些法律处于同一效力层级，不能把《国家安全法》画成效力高于其他法律的一层 |
| 行政法规 | 网络数据安全管理条例、关基保护条例、商用密码管理条例、未成年人网络保护条例、互联网信息服务管理办法 | 由国务院制定，在法律框架内细化制度；《互联网信息服务管理办法》虽然名为“办法”，仍属于行政法规 |
| 部门规章 | 网络安全审查办法、数据出境安全评估办法、个人信息保护合规审计管理办法、人民银行 3 号令和 4 号令等 | 按制定机关、法定职权和适用范围细化规则；行业规章不会仅因“更专项”就自动优先于法律 |
| 行政规范性文件 | 网络产品安全漏洞管理规定、国家网络安全事件报告管理办法、AI 生成合成内容标识办法、银行保险机构数据安全管理办法等 | 提供实施和监管要求；发生违法行为时，还要沿文件的责任条款追溯有权设定处罚的法律、法规或规章 |

各文件的制定机关、发布形式及依据见下方对应官方文本。名称中的“条例”“办法”“规定”“指引”有助于检索，不能单独决定效力层级。本页没有展开地方性法规、地方政府规章和技术标准，涉及属地或行业特殊要求时需另行核验。

### 三部基础法律交叉适用，专项文件按场景叠加

[网络安全法][src-csl]主要约束网络运行、产品服务、关基保护和应急处置；[数据安全法][src-dsl]覆盖数据处理活动及其安全保护；[个人信息保护法][src-pipl]围绕个人信息处理合法性、个人权益和处理者责任展开。同一支付系统处理客户交易数据时，可能同时落入三部法律的适用范围。

下面是**主题关系图**，帮助找到阅读路径。箭头表示从基础制度到专项实施的联系，不代表每份文件只有图示这一部上位法，也不代表前一项完成后才能开始后一项。

```text
网络与系统安全
  网络安全法
    ├─ 关基保护条例 → 关基运营者的重点保护
    ├─ 网络安全审查办法 → 特定采购、平台数据处理等审查场景
    ├─ 网络产品安全漏洞管理规定 → 发现、报告、修补与披露
    └─ 国家网络安全事件报告管理办法 → 分级、首报、续报与总结

数据与个人信息保护
  数据安全法 + 个人信息保护法 + 网络安全法
    └─ 网络数据安全管理条例
         ├─ 网络数据安全风险评估办法 → 重要数据评估与报送
         ├─ 个人信息保护合规审计管理办法 → 合规审计
         └─ 人脸识别、网络身份认证、小型处理者等专项规则

数据跨境
  数据安全法 + 个人信息保护法 + 网络数据安全管理条例
    └─ 促进和规范数据跨境流动规定 → 判断范围、门槛与豁免
         ├─ 数据出境安全评估办法
         ├─ 个人信息出境标准合同办法
         └─ 个人信息出境认证办法

平台、App 与 AI 服务
  网络安全法 + 数据安全法 + 个人信息保护法
    + 互联网信息服务管理办法 + 未成年人网络保护条例
      └─ 内容生态、App、算法推荐、深度合成、生成式 AI、
         合成内容标识、网络暴力、拟人化互动等专项规则

密码、可信身份与行业要求
  密码法 → 商用密码管理条例 → 密评办法、关基商密规定
  电子签名法 → 电子签名效力及电子认证服务责任
  金融业务 → 人民银行数据安全、事件报告和银行保险专项要求
  汽车业务 → 汽车数据安全规定
  涉诈风险 → 反电信网络诈骗法中的主体义务
```

**跨境规则要组合阅读。** [2024 年跨境流动规定第 13 条][src-crossborder]明确，此前数据出境评估和标准合同办法与其不一致的，适用该规定。不能直接沿用旧办法中的全部门槛；也不能把免于申报安全评估、订立标准合同或通过认证，理解为免除个人信息保护等其他义务。

**报告义务要按接收部门分别核对。** [国家事件报告办法][src-national-report]与[人民银行 4 号令][src-pbc-report]的适用对象、分级和时限并不完全相同。向人民银行报告，不当然替代向网信、公安、关基保护工作部门或者其他行业主管部门履行的报告义务。应当按主体、事件类型、报告对象和起算时点建立一张并行报送表。

**金融文件必须先辨明管理对象。** [2020 年监管数据办法第 2、4 条][src-regulatory-data]管理的是监管部门履职形成、掌握的监管数据，适用于监管部门及受托机构；[2024 年银行保险机构数据办法][src-bank-data]管理的是银行保险机构的数据处理活动。普通银行或支付机构不能仅凭名称相似，就把两份文件当成同一套制度。

## 公布与施行时间总览 {#legal-dates}

**日期口径：**“公布／印发”优先使用主席令、国务院令、部门令或印发通知的落款日期；“施行”使用对应版本的生效条款。网页上网日、媒体报道日、本站文章更新时间不替代法律文件日期。修订文件标明“修订／修正”，不将该日期误写为首次制定日期。

## 处罚与其他法律后果 {#legal-liability}

罚款需要同时看**违法行为、适用主体、主观及客观情节、后果和责任条款**。下表选择与企业安全治理直接相关的典型情形，金额均为人民币；不是各文件全部罚则，也不意味着触犯文件任一条款就适用该表最高档。

### 基础法律中的典型处罚

| 违法情形与依据 | 组织／经营主体后果 | 直接责任人员后果 |
| --- | --- | --- |
| 网络运营者未履行网络安全保护义务，适用[网络安全法第 61 条第 1 款][src-csl] | 责令改正、警告，可罚 **1万—5万元**；拒不改正或导致危害网络安全等后果，罚 **5万—50万元** | 后一档对直接负责的主管人员和其他直接责任人员罚 **1万—10万元** |
| 关基运营者未履行第 61 条第 2 款列明的保护义务，适用[该款][src-csl] | 责令改正、警告，可罚 **5万—10万元**；拒不改正或导致危害后果，罚 **10万—100万元** | 后一档罚 **1万—10万元** |
| 前述保护义务违法造成严重或特别严重后果，适用[网络安全法第 61 条第 3 款][src-csl] | 大量数据泄露、关基丧失局部功能等严重后果：**50万—200万元**；关基丧失主要功能等特别严重后果：**200万—1000万元** | 对应两档分别为 **5万—20万元**、**20万—100万元**；不能脱离后果条件引用“最高千万元” |
| 关基运营者使用未经安全审查或审查未通过的网络产品、服务，适用[网络安全法第 67 条][src-csl] | 限期改正、停止使用、消除影响，罚 **采购金额的 1—10 倍** | **1万—10万元** |
| 违法开展网络安全检测、评估或发布漏洞等安全信息，适用[网络安全法第 65 条][src-csl] | 警告、改正，可罚 **1万—10万元**；拒不改正或情节严重，罚 **10万—100万元**，并可停业、关闭网站或 App、吊销许可或执照；达到第 61 条第 3 款后果的，转适用该款 | 拒不改正或情节严重档：**1万—10万元**；更严重后果按所转引条款 |
| 不履行数据安全保护、风险监测、重要数据评估等义务，适用[数据安全法第 45 条第 1 款][src-dsl] | 改正、警告，可并罚 **5万—50万元**；拒不改正或造成大量泄露等严重后果，罚 **50万—200万元**，并可暂停业务、停业整顿、吊销许可或执照 | 一般档可罚 **1万—10万元**；拒不改正或严重后果档 **5万—20万元** |
| 违反国家核心数据管理制度且危害国家主权、安全和发展利益，适用[数据安全法第 45 条第 2 款][src-dsl] | **200万—1000万元**，并可按情况暂停业务、停业整顿、吊销许可或执照 | 构成犯罪的依法追究刑事责任；该款未另列统一个人行政罚款档 |
| 违法向境外提供重要数据，适用[数据安全法第 46 条][src-dsl] | 改正、警告，可并罚 **10万—100万元**；情节严重，罚 **100万—1000万元**，并可暂停业务、停业整顿、吊销许可或执照 | 一般档可罚 **1万—10万元**；严重档 **10万—100万元** |
| 违法处理个人信息或未履行保护义务，适用[个人信息保护法第 66 条第 1 款][src-pipl] | 改正、警告、没收违法所得；违法处理个人信息的 App 可被责令暂停或终止服务；拒不改正的，并罚 **100万元以下** | **1万—10万元** |
| 前述个人信息违法行为情节严重，适用[个人信息保护法第 66 条第 2 款][src-pipl] | 改正、没收违法所得，并罚 **5000万元以下，或者上一年度营业额 5% 以下**；可暂停业务、停业整顿，并通报有关主管部门吊销许可或执照 | **10万—100万元**，并可在一定期限内禁止担任相关企业董事、监事、高管和个人信息保护负责人 |
| 银行业金融机构、非银行支付机构不落实反诈内控、尽调、异常账户及交易监测等列明义务，适用[反电信网络诈骗法第 40 条][src-antifraud] | 较轻情形：警告、通报批评，或 **5万—50万元**；严重情形：**50万—500万元**，并可停止新增业务、缩减业务范围、暂停业务或吊销许可等 | 严重情形下，直接负责的主管人员和其他直接责任人员罚 **1万—20万元** |

个人信息保护法使用的是“**5000 万元以下或者上一年度营业额 5% 以下**”，不能改成两项相加，也不能把“营业额”换成“利润”。适用责任人员罚则时，应核实实际职责与责任认定，不能仅凭 CISO、法定代表人或业务负责人的职务名称推定个人必然受罚。[第 66 条][src-pipl]

**旧条号需要显式校准。** 人民银行 4 号令第 26—28 条发布时引用的网络安全法第 69、59、60 条，在 2025 年修正后的现行文本中，对应检查协助、保护义务及产品服务安全责任的条款分别是第 **70、61、62 条**。应保留 4 号令原文引用的历史条号，同时用[现行网络安全法][src-csl]核对当前法律责任；不能擅自改写法规原文，也不能因旧条号残留就忽略适用法律的变化。[4 号令原文][src-pbc-report]

### 金额之外，还要看经营影响、个人责任和责任适用规则

**业务影响。** 责令改正、约谈、审计、暂停服务、停业整顿、停止新增业务、吊销许可或终止合作，对业务产生的影响不同。其中有行政处罚，也有监管措施或合同后果，不能全部合并称作“罚款”。具体种类和条件分别见[行政处罚法第 9 条][src-administrative-penalty]、[个人信息保护法第 64、66 条][src-pipl]、[银行保险机构数据办法第 76—77 条][src-bank-data]。

**民事与刑事责任。** 给他人造成损害可能需要承担赔偿等民事责任；涉嫌犯罪须依法移送和追责，行政罚款不代替刑事责任。个人信息权益受损还可能触发侵权及公益诉讼，见[个人信息保护法第 69—71 条][src-pipl]与[行政处罚法第 8、27 条][src-administrative-penalty]。业务损失、赔偿金额、行政罚款应分别评估。

**不能机械叠加所有上限。** [行政处罚法第 29 条][src-administrative-penalty]规定，同一个违法行为不得给予两次以上罚款；同一行为违反多个规范应罚款时，按照罚款数额高的规定处罚。多个独立违法行为、单位与个人分别承担责任等问题，仍需根据事实和适用条款认定。

**现行总览不替代历史案件的时间适用判断。** [行政处罚法第 37 条][src-administrative-penalty]规定，原则上适用行为发生时的规定；作出处罚决定时规定已改变且新规定较轻或不认为违法的，适用新规定。2026 年施行的新罚则不能无条件追溯到此前行为。

**整改证据会影响责任判断。** [行政处罚法第 32—33 条][src-administrative-penalty]规定法定从轻、减轻或不予处罚情形；[人民银行 3 号令第 52 条][src-pbc-data]还规定，在能够证明已采取规定保护措施并立即补救等情形下从轻或减轻行政处罚。应保存真实的授权、监测、整改、报送和履职证据；内部问责结论与行政机关认定的法律责任应分别处理。

### 主体身份判断

**主体身份决定适用义务的范围。** 同一家公司可能同时是网络运营者、数据处理者、个人信息处理者、平台服务提供者和行业监管对象，合规工作要先确认身份组合，再映射具体义务。

| 主体身份 | 判断线索 | 重点义务 | 主要法规 |
| --- | --- | --- | --- |
| 网络运营者 | 网络的所有者、管理者和网络服务提供者 | 网络安全保护、等级保护、日志留存、事件处置 | [网络安全法](./网络安全法.md) |
| 数据处理者 | 收集、存储、使用、加工、传输、提供、公开数据 | 数据分类分级、重要数据保护、风险监测、应急处置 | [数据安全法](./数据安全法.md)、[网络数据安全管理条例](./网络数据安全管理条例.md) |
| 个人信息处理者 | 自主决定个人信息处理目的和方式 | 处理合法性、告知及适用时的同意、敏感信息保护、个人权利响应 | [个人信息保护法](./个人信息保护法.md) |

### 典型业务场景

**法规触发点通常藏在业务动作里。** 安全负责人要把合规审查前置到立项、采购、上线、运营、变更和事件处置中，减少业务完成后再补材料的被动状态。

| 业务场景 | 安全负责人要问的问题 | 输出物 |
| --- | --- | --- |
| 新系统上线 | 是否涉及核心业务、个人信息、重要数据、外部访问和第三方组件 | 安全评审记录、等保材料、漏洞扫描记录、上线审批 |
| 云服务或外包采购 | 供应商是否接触系统、数据、账号、日志或生产环境 | 供应商安全评估、合同安全条款、数据处理约定、退出方案 |
| 数据对外提供 | 接收方是谁，目的是否明确，范围是否最小，是否涉及个人信息或重要数据 | 数据提供审批、合同或协议、脱敏方案、接收方监督记录 |
| 数据出境 | 是否向境外组织或个人提供数据，是否触发评估、标准合同、认证或豁免 | 出境路径判断、自评估、标准合同、认证或安全评估材料 |
| App 上线 | 权限是否必要，SDK 是否可控，隐私规则是否清晰，未成年人场景是否存在 | App 合规检查、SDK 清单、权限清单、隐私政策 |
| 内容或社区业务 | 是否有账号、发帖、评论、推荐、举报、内容审核和处置机制 | 内容治理规则、审核记录、投诉举报记录、处置台账 |
| 算法推荐上线 | 是否影响用户选择、交易条件、内容分发或公共舆论，是否满足备案条件 | 算法评估、适用时的备案材料、用户选择机制、干预记录 |
| 生成式 AI 上线 | 是否进入专项规则适用范围，训练数据来源是否合规，输出及合成标识是否可控 | 训练数据治理记录、安全评估、标识方案、投诉处理机制 |
| 安全事件发生 | 是否达到报告条件，是否涉及个人信息、重要数据、关基或行业监管；各报告对象的时限如何起算 | 事件分级、并行监管报告、适用时的用户通知、处置记录、复盘整改 |
