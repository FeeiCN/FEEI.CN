# 网络安全认证、测评与资质体系

安全领域常说的“认证”实际包含**认证、检测、测评、鉴证、备案/审查、合规验证和人员资格**。判断一项要求时，首先看对象、适用条件和法律性质，而不是只问“有没有证”。

## 总览

| 对象 | 国内重点 | 国际/海外重点 |
| --- | --- | --- |
| 企业/组织 | ISO管理体系、特定行业资质与监管评价 | ISO 27001/27701/22301、SOC 2、PCI DSS |
| 系统/环境 | 等保测评、密评、关基安全测评 | PCI DSS、云/客户特定审计 |
| 产品/方案 | 网络关键设备和网络安全专用产品认证/检测、商用密码产品认证 | Common Criteria、PCI PTS/P2PE/Secure Software |
| 人员/机构 | CISP、等保测评/密评相关人员与机构能力 | CISSP/CISM/CISA/CCSP、OSCP、PCI QSA/ISA等 |

## 企业与组织

| 项目 | 类型 | 强制性 | 主要适用场景 |
| --- | --- | --- | --- |
| ISO/IEC 27001 | 信息安全管理体系认证 | 通常自愿/合同驱动 | 企业整体ISMS、海外客户与供应链 |
| ISO/IEC 27701 | 隐私信息管理体系 | 通常自愿 | 隐私治理、数据处理者/控制者 |
| ISO 22301 | 业务连续性管理体系 | 通常自愿 | 关键业务连续性和韧性 |
| ISO/IEC 20000-1 | IT服务管理体系 | 通常自愿 | IT服务组织 |
| SOC 2 Type I/II | 独立鉴证报告，不是认证证书 | 客户/合同驱动 | SaaS、云和B2B服务 |
| PCI DSS | 支付卡数据环境合规标准/验证 | 卡组织生态条件触发 | 存储、处理、传输账户数据或影响CDE的实体 |

PCI DSS覆盖商户、处理机构、收单、发卡和服务提供商等会存储、处理、传输持卡人数据/敏感认证数据，或可能影响CDE安全的实体。

## 系统与运行环境

| 项目 | 类型 | 触发方式 | 说明 |
| --- | --- | --- | --- |
| [等级保护测评](./01-网络与基础设施安全/01-等级保护/index.md) | 法定制度下的系统测评 | 等保对象按适用要求 | 不称“等保认证”；定级、备案、建设、测评、整改是完整闭环 |
| [商用密码应用安全性评估](./01-网络与基础设施安全/03-密码与密评/index.md) | 专项安全评估 | 法规规定的网络与信息系统 | 验证密码应用是否合规、正确、有效 |
| [关基安全测评](./01-网络与基础设施安全/02-关键信息基础设施/index.md) | 关基专项测评 | 被依法认定的关基 | GA/T 2182等与等级测评结果结合 |
| PCI DSS | 支付卡数据环境验证 | PCI生态范围触发 | 范围围绕CDE及能够影响CDE安全的系统和人员 |

## 产品与解决方案

### 网络关键设备和网络安全专用产品

列入现行目录的产品，应按照相关强制性国家标准，经具备资格的机构**安全认证合格或者安全检测符合要求**后方可销售或者提供。现行制度不是简单沿用旧的“安全专用产品销售许可证”概念。

2023年调整后的目录包括网络关键设备（如达到门槛的路由器、交换机、服务器、PLC）和防火墙、IDS/IPS、数据备份恢复等网络安全专用产品。认证按CNCA-CCIS-2023规则实施；认证/检测结果由官方统一发布并可查询。

### 商用密码产品认证

纳入商用密码产品认证目录的产品按照相应认证规则和技术标准开展认证。2025年市场监管总局、国家密码管理局发布第三批目录，继续扩展SM9密钥管理、PLC密码模块、DTLCP、SSH密码模块等产品范围。

### 国际安全产品评价

| 项目 | 对象 | 主要价值 |
| --- | --- | --- |
| Common Criteria / ISO/IEC 15408 | IT安全产品 | 对安全功能和保障能力进行标准化评价，常用于政府、关键行业采购 |
| FIPS 140-3 / CMVP | 密码模块 | 美国/加拿大密码模块验证生态，政府及供应链常见 |
| FedRAMP | 美国联邦云服务 | 云服务面向美国联邦机构的授权体系，并非普通产品认证 |

### PCI产品与方案

| PCI体系 | 对象 |
| --- | --- |
| PCI PTS POI | POS、PIN输入等支付交互设备 |
| PCI PTS HSM | 支付HSM |
| PCI P2PE | 点到点加密Solution、Component、Application |
| PCI Secure Software | 支付软件产品 |
| PCI Secure SLC | 支付软件厂商的软件安全生命周期 |
| PCI MPoC | 移动设备上的支付受理解决方案 |

PA-DSS已经退役，由Secure Software和Secure SLC体系承接；选择产品时应核对PCI SSC官方listing中的具体产品、版本和有效状态。

## 人员与专业机构

### 国内

| 项目 | 侧重点 | 备注 |
| --- | --- | --- |
| CISP | 综合信息安全专业能力 | 国内较常见的人员能力认证 |
| CISP-PTE等方向 | 渗透测试等专项能力 | 按岗位价值判断，不是企业法定合规证明 |
| 等保测评相关人员/测评机构能力 | 等级保护测评 | 应区分机构能力要求与个人培训证书 |
| 密评从业人员/密评机构 | 商用密码应用安全性评估 | 属于密评专业实施能力体系 |

### 国际

| 项目 | 侧重点 |
| --- | --- |
| CISSP | 综合安全架构与管理 |
| CISM | 安全管理与治理 |
| CISA | IT审计 |
| CCSP | 云安全 |
| OSCP / OSCE³ | 攻防与渗透测试 |
| GIAC系列 | 细分安全技术领域 |
| PCI QSA | PCI DSS第三方评估专业资格体系 |
| PCI ISA | 企业内部PCI安全评估人员 |
| P2PE Assessor | PCI P2PE独立评估 |

人员证书主要证明个人知识、经验或专项能力，不能替代企业、系统或产品必须完成的认证和测评。

## 如何判断“必须做吗”

建议统一维护以下字段：

| 字段 | 示例 |
| --- | --- |
| 对象 | 企业 / 系统 / 产品 / 人员 |
| 类型 | 认证 / 测评 / 检测 / 鉴证 / 资格 |
| 地域 | 中国 / EU / 美国 / 全球 |
| 触发条件 | 法律强制 / 条件触发 / 合同要求 / 自愿 |
| 主管/规则机构 | 网信、公安、密码管理、PCI SSC、ISO体系等 |
| 周期/有效期 | 按具体制度和证书执行 |
| 官方查询 | 是否存在官方证书、产品或机构查询库 |
| 证据 | 证书、报告、listing、备案/评估记录 |
| 关联控制 | 等保 / 关基 / 密评 / PCI / 供应链 |

企业真正需要的是一张**适用性矩阵**：先判断业务、系统、产品和人员分别落入哪些制度，再决定必须完成什么，而不是追求证书数量。

## 典型组合

**中国重要支付系统：**等保 + 密评；属于关基时再叠加关基专项要求和测评。

**中国网络安全产品厂商：**先判断产品是否进入网络关键设备/网络安全专用产品目录；命中时完成安全认证或检测。涉及商用密码产品时再判断商密产品认证。

**全球支付机构：**组织层可采用ISO 27001等体系；卡数据环境落实PCI DSS；支付终端、HSM、P2PE和支付软件分别判断对应PCI产品标准；具体国家继续叠加当地金融和网络安全监管。

## 使用原则

认证不是目标。对每项认证/测评都应回答：**为什么适用、覆盖什么对象、证明什么、不证明什么、何时失效、变化后是否需要重新评估。**
