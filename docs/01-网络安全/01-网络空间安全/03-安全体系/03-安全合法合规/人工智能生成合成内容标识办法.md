# 人工智能生成合成内容标识办法

本文用于把AI内容标识要求落到生成、导出、传播、平台识别和用户交互的完整链路。

[法规概览](#overview) · [安全要求与实施](#requirements) · [如何开展检查](#assurance) · [法规原文](#reference)

## 法规概览 {#overview}

| 项目 | 内容 |
| --- | --- |
| 法规 | 《人工智能生成合成内容标识办法》 |
| 生效日期 | 2025年9月1日 |
| 主要适用对象 | 符合算法推荐、深度合成、生成式人工智能相关规定情形的网络信息服务提供者 |
| 核心问题 | 显式标识、隐式标识、内容传播识别、用户声明、元数据和标识完整性 |
| 官方来源 | [国家互联网信息办公室](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm) |

下文按 **“法规要求 → 落实要求 → 怎么检查”** 展开。标识办法需要与深度合成、生成式人工智能、算法推荐等规则一起适用。

## 安全要求与实施 {#requirements}

### 在应标场景添加显式标识

**法规要求｜第4条等。** 对办法规定的生成合成服务和内容，应按文本、音频、图片、视频、虚拟场景等不同载体添加用户可明显感知的显式标识。

**落实要求。**

- 建立“哪些产品/功能/内容需要显式标识”的场景清单，不依赖研发人员临时判断。
- 文本、图片、音频、视频等分别设计不会被正常使用流程轻易遮挡或丢失的标识方式。
- 生成、编辑、导出、分享等不同入口保持标识一致，避免只在生成界面显示、导出后消失。
- 产品重大变更、新模型和新媒体类型上线时重新评估标识逻辑。

**怎么检查。**

- 随机选择文本、图片、音频和视频生成场景，导出后显式标识是否仍然存在？
- 同一内容通过App、网页、API、批量导出等不同入口时，标识规则是否一致？
- 用户裁剪、二次编辑或转码后，平台是否仍能按照适用规则处理？
- 是否存在“界面上有AI提示，但具体输出内容没有适用标识”的情况？

### 在文件元数据等位置添加隐式标识

**法规要求｜第5条等。** 服务提供者应按规定在生成合成内容文件元数据中添加隐式标识等信息，用于内容识别和溯源。

**落实要求。**

- 将隐式标识写入生成和导出流水线，覆盖适用的文件类型和API输出。
- 隐式标识至少与服务提供者、内容属性等规定信息保持一致，避免多系统写入不同结果。
- 记录标识生成版本和技术规范，升级媒体处理库、转码链路时做兼容性回归测试。
- 对标识写入失败设置监控和阻断/降级策略，不能静默产出无标识内容。

**怎么检查。**

- 随机下载一批输出文件，用独立工具读取元数据，隐式标识覆盖率是多少？
- API和批量任务生成的文件是否和前台产品一样写入隐式标识？
- 最近一次转码/媒体库升级后是否做过标识完整性回归？
- 标识写入失败时系统会告警、阻断还是继续正常发布？

### 对传播环节进行识别和提示

**法规要求｜第6条等。** 提供网络信息内容传播服务的服务提供者，应采取技术措施识别生成合成内容及其标识，并按规定进行提示或添加相应标识。

**落实要求。**

- 在上传、转发、分发等入口识别显式/隐式标识以及其他可用生成合成线索。
- 平台对明确带有AI标识、用户声明为AI生成、疑似AI生成等不同情形建立对应提示和处置规则。
- 不把“不是本平台生成”作为不履行传播环节义务的理由。
- 对误判和漏判建立申诉、复核和模型/规则迭代机制。

**怎么检查。**

- 上传来自其他平台的AI图片/视频，传播平台能否正确识别并提示？
- 删除部分元数据但保留显式标识时，平台会如何处理？
- 用户主动声明“AI生成”时，声明是否进入展示和元数据处理链路？
- 从真实投诉反查误标/漏标案例，是否有复核和规则改进记录？

### 管理用户声明和标识去除风险

**法规要求｜办法相关条款。** 服务提供者应提供适当的用户声明机制，并不得提供或者实施规避、删除、篡改法定标识等违法违规功能。

**落实要求。**

- 对用户上传内容提供清晰的AI生成合成声明入口，并把声明结果传递到内容治理和展示链路。
- 编辑、下载、二次创作功能不得默认移除应保留的法定标识。
- 对“去水印”“清元数据”等能力做场景化安全评估，防止形成规避标识的系统性能力。
- 记录标识生成、识别、修改和用户声明的关键日志，便于争议核查。

**怎么检查。**

- 平台是否存在一键去除本办法要求标识的功能或默认流程？
- 用户二次编辑后再次发布，标识责任是否还能正确执行？
- 给出“用户主动删除元数据再上传”的场景，平台会如何识别和提示？
- 发生标识争议时，能否从日志还原生成、声明、传播和修改过程？

### 把标识要求纳入产品发布和持续测试

**法规要求｜办法整体要求。** 标识义务贯穿生成和传播环节，需要服务提供者持续确保技术实现符合相关强制性国家标准和配套要求。

**落实要求。**

- 将标识测试纳入模型、产品、API、媒体处理和内容分发版本发布门禁。
- 建立媒体类型×入口×输出方式的测试矩阵，覆盖显式、隐式和传播识别。
- 对标识覆盖率、识别率和失败率建立监控，异常可追踪到版本和业务。
- 配套标准更新时由明确责任人评估并推动实现升级。

**怎么检查。**

- 最近一次模型或媒体处理版本发布，测试用例是否覆盖法定标识？
- 线上能否统计应标内容与实际标识内容的差异？
- 新增API或第三方渠道时，是否可能绕开现有标识流水线？
- 标识相关国家标准变化后，谁负责跟踪、何时完成差距分析？
