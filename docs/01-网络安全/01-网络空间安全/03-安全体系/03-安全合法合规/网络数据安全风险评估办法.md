# 网络数据安全风险评估办法

本文把风险评估转成“识别适用对象 → 年度评估 → 重大变化重评 → 报告 → 整改 → 复测”的企业控制闭环。

## 法规概览

| 项目 | 内容 |
| --- | --- |
| 发布 | 国家网信办、工信部、公安部令第24号 |
| 施行 | 2026年8月20日 |
| 核心对象 | 重要数据处理者；一般数据处理者鼓励至少每3年评估一次 |
| 关键时限 | 重要数据每年度评估；完成后20个工作日内报送；监管要求整改的，整改完成后15个工作日内报送整改情况；报告至少保存3年 |

## 安全要求与实施

### 建立年度和重大变化触发机制

**法规要求｜第5条。** 重要数据处理者每年度开展风险评估；安全状态重大变化可能产生不利影响时及时评估变化部分。

**落实与验收。** 将重要数据目录、业务变更、数据规模/用途、系统架构、供应商和安全事件接入评估触发器。

**验收证据。** 从重要数据目录逐项反查最近一次评估；随机抽一次重大变更，看是否触发重评。

### 让评估基于生产事实

**法规要求｜第6—15条。** 可自行或委托第三方评估；报告应真实、有效、完整，至少保存3年；评估机构不得转委托，同一机构及关联机构不得连续3次以上承担同一处理者年度评估。

**落实与验收。** 评估直接核验真实数据、系统、日志、权限和处理活动；维护评估机构独立性与轮换。

**验收证据。** 抽一份报告与生产配置、数据流逐项核对；检查近三年评估机构是否违反连续次数限制。

### 报告、整改和复测闭环

**法规要求｜第16—19条。** 重要数据年度评估完成后20个工作日内报送；监管要求整改的，整改完成后15个工作日内报送整改情况；重大风险可能导致停止处理重要数据。

**落实与验收。** 自动计算报送期限；问题必须有责任人、期限、生产复测和关闭证据。

**验收证据。** 从历史评估反查报送回执和整改复测，不接受仅有“整改完成说明”。

### 与密评衔接

**法规要求｜第23条。** 涉及重要数据加密等技术措施的，应依法开展商用密码应用安全性评估。

**落实与验收。** 数据风险评估发现密码保护需求时自动关联密评控制，不重复建设两套证据。

**验收证据。** 抽取一项重要数据加密措施，确认风险评估、密码方案、密评结论与生产实现一致。
