# 知识沉淀

项目结束后，若只留下结论，下次换一个环境就很难复用。知识沉淀要保存的还有：当时为何这样判断，用了什么证据，哪些尝试失败，以及条件变化后应该如何调整。

文章、工具和复盘可以成为专业资产，但写得多不等于理解得深。能找到、能解释、能应用，也能根据反例修改，才说明材料进入了自己的工作方法。

## 保存判断而非只保存摘录

遇到值得留下的材料，先记录来源和上下文，再用自己的话解释它回答了什么问题。引用保留作者与链接，个人推断单独标明，避免整理后把他人观点误当原创。

一条判断记录可以包含：问题、适用场景、关键假设、行动、观察结果、反例和下次检查项。没有经历过验证时，明确写成待检验假设。

## 让表达暴露理解缺口

尝试不看原文解释机制，再回到材料核对。讲给别人时，认真记录对方追问；答不上来的问题正是下一轮学习对象。表达清楚有助于发现缺口，但不能代替事实验证。

阅读、练习、讨论与教授适合不同任务，没有适用于所有学习的固定效率排序。关于检索练习与分散练习等方法，可参考[Dunlosky 等对学习技术的综述](https://doi.org/10.1177/1529100612453266)；具体效果仍受任务与实施方式影响。

## 用真实任务检验能否调用

在下一次相关任务中调用旧记录，比较环境差异，写下哪些部分有效、哪些部分需要修改。实际应用比收藏数量更能暴露知识缺口。

例如同一防护组件在新业务里失败，应检查权限、部署位置、数据流与攻击条件，而非直接认定过去经验毫无价值。保留失效条件，会让方法更可靠。

## 给知识库设置查询入口

按问题和对象建立索引，让自己能从“遇到什么问题”找到材料。稳定命名、关键词、原始来源和相关链接，比不断更换笔记软件更重要。

个人草稿与团队正式知识分开。正式材料注明负责人、适用版本和验证方式；敏感内容按权限保存。过时材料标明状态或归档，不让旧方案与当前规范难以区分。

## 区分复盘、汇报与公开写作

复盘用于改进判断；汇报用于让相关方了解结果、风险和所需决定；公开写作用于分享经过解释与核对的经验。三者可以复用材料，但不能把汇报中的成绩包装直接当作完整复盘。

汇报的结构与交流见[沟通与表达](/communication-and-expression)，如何把复盘动作接到项目推进见[持续拿到结果](/sustained-results)。
