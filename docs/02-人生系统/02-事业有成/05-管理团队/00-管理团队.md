# 管理团队

从个人交付转到团队负责后，工作需要同时处理目标、人员、资源与协作。自己能解决难题仍有用，但更需要让团队能够稳定理解任务、作出决定并形成成果。

管理机制可以减少重复救火，不能替代对人的理解与具体支持。规则清楚、反馈直接与尊重个体可以同时成立，没有必要把让人不舒服当成管理目标。

## 先建立运行所需的共同约定

明确团队服务对象、关键目标、成员职责、授权范围、反馈节奏和风险升级方式。既让成员知道预期，也确认资源、权限与工作负荷是否允许完成。

关键岗位保留交接与备份，避免所有判断集中在主管身上。复杂例外仍需要人讨论，不能期待一套流程自动解决全部问题。

## 按管理任务选择阅读

- **招人、分工与培养**：读[知人善用](/managing-people)，用工作证据持续校准人岗匹配。
- **新人融入与阶段判断**：读[试用期管理](/probation-management)，明确目标、支持与双方验证方式。
- **成员依赖主管，交出任务后仍反复重做**：读[培养他人与授权](/coaching-and-delegation)，让任务、权限、支持与责任匹配，再逐步检查独立能力。
- **决策被偏见或层级影响**：读[善决策](/decision-making)，再用[决策的实操清单](/decision-rules)检查具体步骤。
- **规则与实际行为脱节**：读[团队文化](/team-culture)，检查奖励、信息与异议机制。

## 目标与协作不在这里重复展开

目标、里程碑和复盘见[设定高目标](/set-high-goals)、[持续拿到结果](/sustained-results)。跨部门利益与资源协调见[影响协作](/influence)。管理者的绩效评价责任，与员工如何争取准确评价是不同视角，需要明确区分。

遇到方向不明或重大分歧时，可继续看[领导力](/leadership)。[理解阿里的组织优势与困境](/understanding-alibabas-organizational-strengths-and-challenges)是一份基于个人经历的组织分析，用于讨论机制取舍，不作为所有公司的通用结论。

## 用团队状态检查管理效果

持续观察结果、成员成长、风险、工作负荷和表达空间。成果很好但人员长期透支，或氛围和谐但问题不被汇报，都需要检查。

离职、低绩效或项目失败不应自动归因于个人。先确认目标、资源、授权与评价是否合理；涉及劳动关系调整时，依据事实和现行法律处理，不能用文化标签替代程序。
