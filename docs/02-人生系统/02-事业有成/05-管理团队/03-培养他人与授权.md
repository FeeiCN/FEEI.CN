# 培养他人与授权

任务交出去了，主管还是不放心，最后又自己改一遍。几次下来，成员可能不再认真作判断，反正主管总会给最终答案。另一头，只丢一句“你全权负责”，却不给权限和支持，出了问题再追责，也谈不上培养。

难的是决定哪些事让他自己做，哪些地方还需要帮忙。不能只因为主管忙，就突然要求成员独立。下面是一项虚构的安全评估任务，不对应任何真实员工。

## 技术熟练，还不够

这位成员已经能独立处理常见漏洞，但第一次负责完整的业务变更评估。技术检查会做，不代表已经会确定资产范围、协调业务，或判断该不该申请例外。

评估又包含不同风险：安排访谈与整理材料通常可逆，误判数据流可能漏掉重大风险，接受例外和批准发布则需要制度授权。不能因为一个人擅长技术，就一次性把所有判断交给他。

如果很难把职责拆清楚，可以参考[NIST NICE 框架](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center)里的任务、知识和技能描述。最后仍要看这个人实际做过什么，不能对照几个词就认定他已经胜任。

如果任务是不可逆或高风险决定，应先确认正式审批与复核要求。培养空间可以来自缩小范围、测试环境或跟随评审，不能通过取消必要控制获得。

## 哪些事让他自己决定

交任务前，把这些事说清楚：

| 约定项 | 本次安排 |
|---|---|
| 任务结果 | 完成获准业务的变更评估，列出已验证风险、未知项和建议 |
| 可自行决定 | 在批准范围内安排访谈、请求必要材料、选择测试步骤 |
| 需要复核 | 资产与数据流范围、重大风险分类、例外建议和最终报告 |
| 不包含的权力 | 风险接受、例外批准、发布决定及扩大数据访问 |
| 必须主动报告 | 范围扩大、证据不足、发现高影响风险、期限与资源冲突 |
| 支持与备份 | 有业务联系人、获准材料入口，主管或指定同行处理复杂例外 |

还要商量什么时候交、做到什么程度、何时一起看进展。请成员说说准备怎么做，缺什么支持。如果要他负责的事，靠现有权限根本办不到，就先改安排，别等失败后再说他不够主动。

请资深同事帮忙指导，也得给他留出时间。他原有的工作不会自己消失，不能总让他下班后补。

## 先示范一次

先一起看一项有代表性的变更，示范怎么找到数据流和权限变化，哪些信息会影响评估范围。再交给他一项新的任务，让他自己提出方案，说清理由和还没弄明白的地方。

可以问：“你看到了什么？为什么这样判断？如果发现什么情况，你会改建议？”听一听他怎么想。基础知识缺了，就直接讲，没必要把所有指导都变成提问。

若成员不知道某个数据流概念，直接解释并安排新例子验证，比反复问“你再想想”更有效。紧急事件中也可能需要负责人直接指挥，稳定后再还原判断过程。

主管的偏好不能成为隐形验收标准。成员使用不同但符合要求的方案，应比较证据与代价；主管中途改变目标，也要更新约定，不能让成员猜测答案。

## 发现遗漏，别替他改完

假设成员第一份报告只检查新增接口，没有覆盖后台异步导出。主管发现后，不直接改完所有材料，也不笼统评价“考虑不全面”。

可以反馈：

> 这份报告看了同步接口，但材料里还有后台导出。那条数据流没看，权限和保留时间就可能漏掉。你当时怎么定的范围？我们先一起看完一条数据流，报告再由你来改，之后换一个导出任务看看。

也要听听他是不是没拿到完整资料。如果业务方一直没提供材料，主管该帮忙解决，不能把资料缺失全算成成员能力差。

原报告改对了，可能只是记住了这次提醒。换一项任务还能自己找出类似问题，才更让人放心。具体练习方法见[专业判断的训练方法](/professional-practice)。

## 什么时候可以少盯一点

看看他能不能说清资产和数据流，知道哪些已经确认、哪些还在猜，拿不准时会不会及时问，缺材料时能不能找到该找的人。报告按时交了，只说明其中一件事。

几项不同的新任务都能独立完成，就可以少检查一些常规步骤，改为抽查和复杂问题复核。不同任务的风险不一样，没有“做满三次就可以放手”的固定标准。

正式审批仍然保留。成员形成评估能力，不代表可以自行接受组织风险。扩大职责或权限应通过相应流程，不靠口头“你已经很成熟了”越过制度。

遇到陌生业务或更复杂的任务，再多帮一些也正常。一个人会处理常见问题，不代表每种情况都已经见过。

## 交付不符合预期，先查哪里

到期了，报告还是不合格，先别急着给人下结论。要求讲清楚了吗？基础能力够吗？材料和权限拿到了吗？中途有人看过吗？主管如果只在最后一天出现，也得看看自己哪里没帮上忙。

明确条件后，按缺口选择动作：基础能力不足就安排示范与训练；依赖未落实就补资源；任务风险太高就缩小自主范围；持续无法胜任则考虑调整分工。不能因为组织缺人，就把需要长期培养的任务强行变成独立交付。

成员也需要对职责内行为真实说明。隐藏风险、伪造证据和越权操作，不能被笼统解释为培养成本。涉及绩效或劳动关系时，按事实与现行规则处理，和一次辅导讨论分开。

确实需要接手，就说清楚这次为什么接、各自做什么，之后哪些事仍交给他。别一出问题就收回全部任务，然后很久不再给机会。

## 主管不在时，还能不能做

让另一位获准成员依据报告接续一项常见任务，检查材料、权限与升级路径是否可用。文档齐全却没人能接续，说明备份还没有形成，需要实际练习。

培养机会要按任务需要和能力缺口合理分配，避免熟悉成员长期获得关键项目，其他人没有证明机会。授权成果同时承认执行者与支持者的贡献，不把培养包装为主管单方面的功劳。

走到这里，对这位成员的判断可以具体一些：常见变更能自己定范围、提检查方案；复杂数据流仍请同行一起看，审批权不变。下次再看看他能否处理陌生业务、让别人顺利接手。

主管少盯一些细节，才有时间处理目标、资源和难题。培养有没有效果，除了看任务做完没有，也要看成员是不是更能独立工作，团队是不是不再总等同一个人。
