# 创建事业：从真实需求开始验证

从职业能力走向创业，新增的问题是：谁愿意采用或付费，怎样持续交付，成本是否可承受。专业优秀可以帮助解决问题，但不能单独证明商业机会存在。

本文聚焦创业早期验证。它是个人学习与判断框架，不是已经完成创业全周期的成功经验，也不覆盖注册、财税、股权或上市操作指南。

## 从重复痛点寻找问题

观察目标用户正在做什么，哪里反复失败，用了哪些临时办法，损失由谁承担。访谈和重度使用帮助形成线索，但用户口头赞同不等于采用或付费。

手工表格、脚本或多系统搬运可能是痛点，也可能是成本合理的现有方案。先理解它为什么存在、多久发生一次，以及用户是否希望改变，不预设所有手工流程都需要产品化。

## 写出让用户切换的理由

新方案的收益需要抵消学习、迁移、兼容、协作与风险成本。更漂亮或多几个功能，未必足以让用户改变行为。

说明服务谁、改善哪个任务、相比现有办法有什么证据，以及暂时不服务谁。切换理由可以是更可靠、更少损失、更容易完成或更低成本，无需统一承诺好一个数量级。

## 把想法转换成最小实验

每个实验写清假设、目标用户、测试范围、可观测信号、成本上限、期限和停止条件。先用能检验关键假设的最小方案，人工服务或简单原型也可以。

例如验证内部风险报告工具：先获得授权，用允许的数据服务一小组真实使用者，观察他们是否完成原先受阻的判断、是否持续使用，以及维护成本。无需先建设完整平台。

[Reid Hoffman 的《Idea Generators》讨论](https://x.com/reidhoffman/status/2071636465600065765)可以帮助思考自己正在验证什么理论，属于观点材料。判断仍要回到用户行为和实验结果。

## 分发与需求验证同时进行

了解用户在哪里发现替代方案、信任哪些渠道、谁决定采购或采用。早期创始人可能需要亲自拜访和服务用户，以理解实际阻力。

可以参考[Paul Graham 的《Do Things that Don't Scale》](https://paulgraham.com/ds.html)，它提供创业经验，不是每类业务的通用因果规律。接触用户时尊重隐私、拒绝与渠道规则，避免把持续打扰解释成执行力。

## 同时验证收入、成本与现金边界

跟踪付费或采用证据、交付与维护成本、支持负担和现金可维持时间。留存和口碑有价值，但增长不会自动持续，市场规模也不能仅从少数用户热爱推导。

创始人时间是成本，AI 生成原型的速度也不等于真实开发成本接近零。可靠性、运维、数据许可、用户支持和质量验证都需要投入。

收入、利润和现金的基本区别，以及技术成果到经营变化的证据链，见[技术工作者如何理解业务](/business-understanding)。

涉及合同、人员、股权、财税和行业资质时，按经营地现行规定与专业意见处理。未验证经营条件前，避免过早作出长期租约、大额采购或无法撤回的承诺。

## 继续与停止都要基于新增证据

继续的理由可以是重复使用、真实付费、明显改善的任务结果，或新的可检验假设。长期没有信号时，调整用户、方案或停止，比仅延长坚持时间更合理。

复杂机会可能需要较长验证周期，停止条件也可以更新，但要说明新证据与剩余预算。没有证据地继续，容易让过去投入替未来决定。

## 逐步建立能持续交付的组织

验证需求后，再补职责、权限、质量、交接和激励。创始人贴近用户有价值，也需要避免绕过负责人造成多头指挥。重大权益与资源安排应书面明确、依法处理。

初步结果可以是可持续的小生意、独立产品或内部孵化，不一定是大型企业。选择规模时，回到想服务谁、愿意承担什么责任与能承受怎样的风险。团队机制见[管理团队](/manage)，取舍与纠错见[善决策](/decision-making)。
