# 智能工程

智能工程关注如何理解、使用和构建 AI 系统。**一个方法是否值得沉淀，要看它能否在明确约束下产生可验证、可复用的结果，而不是是否用了更新的模型或更多 Agent。** 这里保存通用原理与方法，安全专题独立放在[人工智能安全](/ai-security)。

## 基础认知：理解能力与边界

[AI 基础认知](./01-AI基础认知/01-AI基础认知.md)组织 LLM 技术演进、模型能力边界、上下文工程与 Agent 架构。先明确模型负责哪些判断、外部系统需要提供哪些信息和约束，再选择工具与实现方式。

## 使用实践：把任务变成可验收结果

[AI 使用实践](./02-AI使用实践/02-AI使用实践.md)从任务、上下文、行动约束和外部验收出发，串联研究、编程、Agent、图片生成、Skill、知识管理与模型接入。工具操作放在具体教程中，不在入口页重复维护。

## 趋势判断

[AI 转型](./03-AI转型/03-AI转型.md)保存对技术趋势、组织流程和个人能力变化的判断。将观察、推断与行动选择分开；模型能力的变化不自动等于团队效率或业务价值的变化。具体观点在对应文章中展开，并保留证据和适用边界。

## 项目与实践经验

[AI 项目](./04-AI项目/04-AI项目.md)作为项目与研究入口。阅读时区分项目介绍、个人实践和可复现结论；形成独立复盘后，再记录目标、约束、过程、验证结果与失败原因。

## 内容归属

概念放基础认知，方法放使用实践，组织和个人变化的判断放 AI 转型，具体项目经验放 AI 项目。Prompt、Skill 和工作流先跟随其实际任务沉淀，不因内容形式再复制一个平行目录。

[AI 系统安全](/ai-system-security)讨论被保护对象的边界，[AI 赋能安全](/ai-for-security)讨论安全工作的专用能力，[AI 滥用防御](/ai-abuse-defense)讨论攻击者利用 AI 的风险。安全文章可以引用本目录的通用工程方法，通用教程也应链接相应的安全边界，而不是各维护一份相同正文。
