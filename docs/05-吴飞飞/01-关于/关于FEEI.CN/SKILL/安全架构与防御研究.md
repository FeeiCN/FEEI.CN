## 建设内容的选题与补缺

内容规划、自主选题和建设方法文章的成稿使用本节；开展具体架构与防御研究时，再使用下一节的研究流程。本人已指定主题时，在该主题内完善；其他缺口可以说明，不替换本次任务。

先明确读者正在建设或运行什么，再按需阅读相关总览、已有专题和代表性正文。区分参考资料是否充分、建设方法是否只有概述，以及是否已有能解释实施与验证的专题。目录、篇数和篇幅只用于定位检查范围，不能据此认定能力已经覆盖或要求各栏目数量相近；优先完善既有内容，不为补缺预建空栏目。

自主选题优先检查以下建设方法是否足够具体，并随实际覆盖变化重新判断优先级：

- **资产与责任关联**：资产如何发现和更新，怎样关联业务、责任人及调用关系，遗漏和归属错误如何处理。
- **身份与执行权限**：身份、设备、服务和 Agent 的访问如何授权，权限如何落实到执行与资源侧，例外和撤销怎样生效。
- **监测响应与恢复验证**：需要哪些记录，怎样关联攻击路径、研判和分派异常，以及如何止损、恢复并复测。
- **组织运行与资源取舍**：谁接受风险，例外如何审批和到期，整改怎样升级，以及有限资源如何确定投入顺序。

建设方法文章从具体业务场景展开，说明控制位置、组织责任、实施步骤、方案取舍和验证依据；尚未验证的方案保留假设与实验边界，缺少公开实践时不编造落地经历。成稿按内容需要组织，不强制统一章节。

法规与标准、通用 AI 基础、招聘材料和历史演讲继续按各自职责维护。资料数量较多不构成删除理由，也不自动提高继续扩充同类资料的优先级；内容建设的取舍以当前问题、已有覆盖和证据为依据。

## 架构与防御研究

研究可验证、可迁移的安全架构与防御方法，保持既有安全架构研究范围，不改变其他研究任务的职责。先阅读相关安全架构、身份、访问控制、云、应用、数据及 Agent 安全文档与可访问的历史研究。

从标准正文、官方技术文档、原始论文、真实事件报告和修复提交中选一个本周值得推进的防御问题，核实时间、版本、适用条件与证据层次。围绕具体场景建模：资产、参与方、攻击者能力、入口、信任边界、安全不变量、可达危险副作用、现有控制及旁路。

最多提出两项架构假设或改进方案。研究记录包含稳定 ID、与已知方案的增量、证据与反证、替代设计、安全覆盖、残余风险、任务可用性、时延、成本、运维复杂性、证伪条件和可执行评测计划。没有新证据时推进旧假设，允许证伪或阻塞，不为数量立项。通过已授权的源码与规范分析核查；没有可用隔离环境时，只设计实验，不把模拟规则当作真实防御有效性的证明。

按来源 URL、DOI、根因、不变量、稳定 ID 和已发文章去重。状态按 Candidate → Hypothesis → Evidence Review → Experiment Designed → Verified/Falsified/Blocked → Pattern/Reference Architecture 延续，保留日期、证据等级、反例与下一步。

每月首次运行对比至少两种架构方案的防护覆盖、残余风险和工程成本，明确实验缺口。周期复盘不强制发周报或月报。

成熟成果面向资深安全工程师、架构师和 CISO，用一个具体问题解释风险机制、关键数据/权限边界、控制为何生效或失效，以及方案取舍和验证方法。必要的架构图应呈现边界、责任或控制关系，不能把段落逐条装框。完整待审稿优先完善既有相关文章，按共用约定交付公开 Issue。
