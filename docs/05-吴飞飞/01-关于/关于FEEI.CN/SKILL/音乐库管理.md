用于音乐点歌 Issue、歌曲添加与删除、歌词及播放器维护。用户要求“运行音乐库管理 SKILL”或批量处理点歌时，默认完成检索、下载、上传、歌单发布、回执与关闭，不逐首重复确认已明确的操作。仅询问或审阅本文件时不启动处理。交互执行须有对应的服务器、仓库发布与 Issue 写权限；在 workflow 中调用时仍遵守该 workflow 的权限，不能靠本文件扩大权限。

## 批量处理音乐 Issue

1. **找出有效点歌。** 在当前仓库检索本人创建、未关闭、标题为“音乐 歌名”或“音乐：歌名”的 Issue，读取正文及本人全部评论，以最新要求确定歌名、歌手和版本。不要把正文偶然提到音乐的文章、播放器功能建议当作点歌。批量检索翻页读全，先列曲目和已有收录情况。
2. **核对版本与去重。** 优先使用本人指定的歌手和版本；仅给歌名时先核对原唱及专辑录音，无法可靠确定的只询问该首，其他明确曲目继续处理。对照 `playlist.ts`、歌词映射和服务器实际文件；同一录音已有收录时复验即可，不重复下载或注册。本人指定的现场、翻唱和混音保留版本标识。
3. **下载并检查。** 按下节取得完整音频与对应歌词。临时目录记录每首的 Issue、版本、来源、文件相对路径、时长、哈希和实际进度；音频与歌词放入 `static/music/`。确认文件可解码、音质格式及录音版本正确，再登记歌单并增量生成歌词映射。
4. **定向上传。** 清单只列本批音频和歌词，使用下文脚本先预览、再上传。校对服务器 SHA-256 与本地一致；音频完整解码无错误，公网链接可访问、支持音频分段读取，歌词内容一致。随后运行本批需要的类型检查、文档检查和构建，只提交本任务文件到 main 并推送，核对部署及适用的播放器检查结果。
5. **验证正式站点。** 打开 `https://feei.cn/?music=open`，逐首搜索、点选并检查实际播放进度、完整时长及同步歌词加载。桌面和手机都检查，浏览器夹具测试不能代替真实音频。下载成功、提交成功或部署成功都不能单独作为点歌完成依据。
6. **回执并关闭。** 交付前复读 Issue，确认本人没有改歌或取消。按下文回执要求留言，成功写入回执后再关闭并回读状态。有部分失败时分别交付，成功曲目关闭；失败曲目注明实际缺口并保持打开。重跑先核对已有完成回执和线上成果，避免重复发评论或重新下载。

检索入口：`gh issue list --repo FeeiCN/FEEI.CN --state open --author FeeiCN --search '音乐 in:title' --limit 100 --json number,title,body,url`。达到上限时继续分页，再按上述标题形式筛选；评论另行读全。

## 音源与歌词获取

优先使用用户提供的来源，当前点歌下载入口为[无损音乐下载](https://flac.music.hi.cn/)。搜索“歌名 歌手”，按歌手、专辑、录音版本和时长选曲；默认优先 FLAC，可用音源只有 MP3 时保留实际格式，不转码冒充无损。排除误匹配的铃声、试听片段、伴奏、现场、混音与同名翻唱。

该站是动态页面，搜索入口当前为 `POST ajax.php?act=search`，表单包含 `platform=kuwo`、`keyword`、`page`、`size`，结果提供 `id`、`name`、`artist`、`album_name`、`duration`、`minfo`。先从本轮页面核对接口，再使用；下载通过页面正常的“下载 → 音质 → 点击下载”取得实际地址。浏览器复用本项目会话，遇到并行任务时固定本任务标签页。构建文件名、签名参数和 CDN 地址可能变化，不写入长期规则或仓库。出现登录、口令、验证码或额度限制时按站点流程处理，不能修改验证状态或绕过拦截；只询问确实缺少的输入。

格式和时长用 `ffprobe` 或 `mutagen` 核对，完整解码用 `ffmpeg -v error -i 音频文件 -f null -`；本地无工具时可在已授权的服务器上验证。

同步歌词优先用同版本的已有 LRC、下载站歌词或 LRCLIB；必要时可核对网易云公开的歌曲搜索与歌词接口。按歌手、版本、时长及关键段落时间检查对应关系。歌曲接口未提供完整音频时不能把错误页或试听段登记成完整歌曲。保留韩文、英文等原歌词；翻译只作补充，不能替代原词。纯文本歌词保存为 `.lyrics.txt`，不能平均分配时间戳后声称已取得同步歌词；缺少同步歌词时在回执中如实说明，未达到本人要求则保留 Issue。

网易云已用过的公开入口是 `https://music.163.com/api/search/get/web`，查询参数为 `s=歌名 歌手&type=1&offset=0&limit=10`；核对结果中的歌手、专辑和时长后，用歌曲 ID 请求 `/api/song/lyric?id=歌曲ID&lv=-1&kv=-1&tv=-1`，读取 `lrc.lyric` 保存为同名 `.lrc`。接口失效时改用可核验的来源，不把整个 JSON 或译文误存为原歌词。

`download_music_lyrics.py` 支持只处理本批已注册且本地存在的音频；可重复传入 `--audio-file`。已下载的非空 LRC 会直接复用，脚本合并旧映射，不因旧音频仅存在服务器而删掉其歌词引用：

```bash
python3 scripts/download_music_lyrics.py --audio-file '歌名-歌手.flac'
```

查看处理报告中的结果，不能只看进程是否退出。没有指定文件时处理本地可用歌曲，仍保留歌单中仅在服务器存在的歌词映射；已从歌单移除的歌曲才清理映射。生成文件 `localLyrics.ts` 继续由脚本维护。

## 上传本批文件

`sync-static-assets.sh` 的默认模式会同步整个音乐与媒体目录；点歌使用 `--music-files-from`，每行一个相对于 `static/music/` 的现存文件路径，含本批音频和歌词，不列目录或无关文件。下例的 `music_batch_files` 表示已生成清单的完整路径：

```bash
bash scripts/sync-static-assets.sh --music-files-from "$music_batch_files" --dry-run
bash scripts/sync-static-assets.sh --music-files-from "$music_batch_files"
```

此模式仅上传清单内文件，不同步 `static/media/`，也不允许 `--delete`。服务器位置和连接参数由脚本维护；凭证不写入 SKILL、评论或日志。资源通过已有共享音乐目录提供，音频、歌词和临时下载缓存不进入 Git。

## Issue 回执

完成评论简短写明歌名、歌手、版本、实际格式与时长，给出可打开的歌单、提交和实际部署或检查链接，说明逐首线上播放、歌词和文件完整性的核验结果。使用 `<!-- music-library:delivered:提交SHA -->` 标记本版交付，便于重跑核对。不要贴歌词全文、临时签名下载地址或未执行的验证。

正文先写临时文件，再按顺序留言、关闭，任一步失败都保留实际状态供重试：

```bash
gh issue comment "$music_issue" --repo FeeiCN/FEEI.CN --body-file "$music_result_file"
gh issue close "$music_issue" --repo FeeiCN/FEEI.CN --reason completed
```

受阻时只说明已完成阶段、缺口和继续条件，不用“已完成”标记；完整交付后才以 completed 关闭。最后汇报本批 Issue 状态、实际新增或复用的歌曲、提交与验证结果。

## 音频文件

所有音频文件统一放在 `static/music/` 下。

- 文件命名：`歌名-歌手.扩展名`，例如 `大海-张雨生.flac`、`MineMine.wav`。
- 周杰伦专辑类放到 `static/music/周杰伦/`，playlist 注册时保留子目录前缀，例如 `周杰伦/一路向北.wav`。
- 扩展名支持 `mp3` / `wav` / `flac`，URL 通过 `toEncodedUrl` 编码，并统一生成 `https://feei.cn/music/...` 完整地址。
- 不直接引用其他站点的音频，文件先本地化；播放器请求本站共享音频目录的完整地址，不将大文件加入 Git。

## playlist 注册

`playlist.ts` 的三个基础分组继续保留：`favoriteTracks`（我喜欢的音乐）、`jayTracks`（周杰伦）、`ambientTracks`（白噪音）。宝宝音乐从 `https://feei.cn/music/baby-music/manifest.json` 按需载入，筛选和歌手分组由现有工具函数派生。

在对应分组末尾追加 `localTrack('歌名', '歌手', '文件名')`，函数根据 `localLyricsFileByAudioFile` 自动挂载歌词：

```ts
localTrack('大海', '张雨生', '大海-张雨生.flac'),
```

## 歌手归属与字段一致性

- 合作歌手用 `&` 分隔，例如 `'周杰伦 & 费玉清'`。
- `primaryArtistOf` 取主要歌手归一，避免合作版本产生重复歌手条目。
- 同一首歌不要在多个基础分组重复注册；KTV 等维度使用派生筛选分组。
- 不同版本（live/remix/cover）可以独立注册，文件名后缀区分。

## 歌词映射

`src/components/GlobalMusicPlayer/localLyrics.ts` 由脚本生成，不手工编辑；下载与增量生成方式见“音源与歌词获取”。

## 添加与删除

添加单曲时，先放好音频，在 playlist 注册，再生成歌词映射。删除时同步移除 playlist 条目、音频及对应歌词，并重新运行映射脚本，避免留下失效引用。

## 播放器结构与交互

音乐统一由 `src/theme/Root.tsx` 挂载的 `GlobalMusicPlayer/Client.tsx` 播放。顶部导航右侧的 `GlobalMusicPlayer/NavbarButton.tsx` 提供音乐入口，`GlobalMusicPlayer/Controls.tsx` 提供选歌面板及手机播放后的底部迷你条，`MusicLibrary` 仅作为面板内部按需加载的选歌组件，不再单独发布音乐库页面。歌曲数据仍在 `src/components/GlobalMusicPlayer/playlist.ts`，不要建立第二套播放器或重复歌单数据。

`/my-playlist` 保留为兼容入口，转到首页并打开选歌面板。任意站内页面使用 `?music=open` 可打开面板；打开面板不自动播放，点选歌曲后才播放。文章内 `MusicTrackPlayer` 继续通过事件控制同一个播放器。原生播放列表按钮也打开这个选歌面板，全屏歌词由用户主动打开。

选歌面板在当前标签页的会话中保留歌单、歌手、搜索词和滚动位置，收起窗口、展开或收起播放控制、换页及刷新后均可恢复。歌单选择器仅展示常用歌单与分类，歌手使用独立的搜索筛选；曲名搜索覆盖全库。“定位当前歌曲”会清除筛选，切到歌曲所属歌单并滚动至当前曲目，不重新播放歌曲。

窗口默认展示选歌列表，不使用顶部切换页签。搜索独占一行，歌单和歌手筛选并排一行，统计和当前歌曲定位放在列表上方；歌曲按歌单顺序展示歌名与歌手。播放后的当前歌曲固定在窗口底部，可暂停或切换下一首，点击歌曲信息在底部原地展开进度、播放控制和辅助工具，再次点击收起。歌单始终保留，不切换详情页面，也不重新挂载列表；展开状态通过箭头及 `aria-expanded` 表达。

顶部入口、迷你条和当前歌曲区域共用加载中、播放中、已暂停及加载失败的状态。顶部悬停提示包含歌名和歌手；迷你条加载失败时可直接重试。当前歌曲使用紧凑封面与歌名、歌手标识，展开后依次展示进度、上一首／播放／下一首，以及顺序、循环、音量和歌词工具；紧凑状态保留暂停与下一首，避免重复展示主控制。展开与收起使用 Chakra Collapsible，并遵循减少动态效果的系统设置。音量使用独立弹层。窗口使用站点强调色，长歌名最多展示两行并保留完整文字提示。

## 验证与发布

本地运行 `npm run start`，在任意页面打开顶部导航右侧的音乐按钮，检查搜索、歌单和歌手选择、点选播放、暂停收起、进度恢复、换页连续播放和主动切换全屏歌词。桌面面板位于顶部入口下方，再点入口可收起；收起后仅保留顶部入口与播放状态，不显示另一份底部窗口，也不为其增加正文底部留白。手机使用底部对话框，锁定背景滚动并约束键盘焦点；仅在手机宽度（不超过 640px）播放后显示底部迷你条，可暂停、切歌或切回面板。未播放时不显示迷你条及当前歌曲底栏；手机停止播放并收起会暂停音频、隐藏迷你条。顶部图标显示播放和展开状态。验证收起面板后焦点回到入口按钮，`/my-playlist` 与 `?music=open` 都能打开面板且不会自动播放。桌面和手机宽度都要检查溢出、滚动和关闭入口。

遵循仓库构建与发布流程。音乐组件相关 PR 通过 `music-player-check.yml` 执行类型检查、文档检查、构建及浏览器回归；浏览器测试使用生成的音频夹具，不替代上线后对真实音频文件的检查。

调整选歌交互后，检查会话恢复、歌手搜索、当前歌曲定位、播放控制原地展开收起、列表滚动位置和手机弹层焦点；调整状态反馈后，用音频请求失败及延迟场景验证重试、加载、暂停与播放状态。检查音量弹层的键盘操作、长歌名、小屏幕上的进度条和主要播放按钮，以及深浅主题。
