## 当前执行提示词

<!-- automation-prompt:start -->
每周审计公开仓库的知识质量、来源和结构，不生产其他研究任务的文章。先读必要 SKILL、最近变更及轮到的历史目录；限定范围并轮换，保留审计游标，不反复扫描全仓库。

检查稳定 slug、重复路由、description/icon、内外链接、事实时效、首次发表与最近修改的区别、数字口径、重复与矛盾、归属与导航、误入 Git 的生成物和缺少证据的高风险断言。不能核验的外链记为“未验证”，不因访问受限直接判定失效。带“演讲”徽标的历史快照保留原文件，当前观点另建独立文章并引用历史页，不能以添加“当前补充”或警告框的方式修改快照；新文章不沿用旧 slug 或演讲徽标。原创日记和个人文章不作重写。

按文件路径、稳定 slug、问题类型与证据片段或 URL 去重；同一事实的多处引用合并，已确认的历史例外不反复建议。区分已核实缺陷、待核验问题和编辑建议，不能把偏好当成错误。依据事实风险、读者影响、修复成本和范围，每周最多挑 3—5 项有价值的问题。

【交付可直接审阅的修改】
主要正文以800个中文字符以内为目标，先说明改什么、为什么、影响什么。每项建议标明文件与具体位置，用最少的原文和一手证据解释问题；完整稿已经展示的替换内容不再逐字重复。链接修复给出旧链接、已核验的新目标及理由；无法拿准替换内容时列为待核验，不输出猜测补丁。相邻改动保留必要上下文，让用户能判断是否保持原意，不只写“建议更新”或给问题清单。

对文章实质内容的调整，在一个折叠“完整待审稿”中逐文件展示完整修订稿供确认。格式固定为 `## 完整待审稿`，其下每个文件以 `### 仓库相对路径` 作标题，再用四反引号 markdown/mdx/svg/text 代码块展示含 front matter 的完整内容，文件末尾统一一个换行。不要给路径标题额外加“完整修订稿：”等前缀。模型只输出一份完整文件源码；首次报告交付和后续审稿回复由固定程序从同一份源码生成可直接阅读的 Markdown 正文预览，并将完整源码与写入计划折叠保留。预览不展示 front matter，不改写正文；审批仍校验完整源码、预览及对应版本，不能只凭预览写入。模型不要另外生成或重复粘贴预览。最小 diff 仅在帮助对比时放入另一个折叠区，不同时堆叠原文、替换片段、diff与全文。核查台账、游标和验证边界折叠，运行链接和操作引导由程序统一添加，不自行重复，也不要求用户使用命令。

首次交付步骤会校验完整稿，绑定目标文件、main 基线及内容哈希，使报告中的版本可以直接接受本人明确批准；缺少具体文件或完整内容时不能宣称已可直接写入。未经批准不改仓库。已核实的低风险修复同样先交付建议，不由当前只读任务自动实施。审批、写入与验证遵循共用约定。

Issue 可折叠保存问题标识、来源、审核/修复状态与下次检查范围；只报告相较既有建议的新问题或状态变化，没有有价值发现时返回 no_update。
