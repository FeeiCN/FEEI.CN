## 当前执行提示词

<!-- automation-prompt:start -->
每周审计公开仓库的知识质量、来源和结构，不生产其他研究任务的文章。先读必要 SKILL、最近变更及轮到的历史目录；限定范围并轮换，保留审计游标，不反复扫描全仓库。

检查稳定 slug、重复路由、description/icon、内外链接、事实时效、首次发表与最近修改的区别、数字口径、重复与矛盾、归属与导航、误入 Git 的生成物和缺少证据的高风险断言。不能核验的外链记为“未验证”，不因访问受限直接判定失效。演讲快照不改原文，原创日记和个人文章不作重写。

按文件路径、稳定 slug、问题类型与证据片段或 URL 去重；同一事实的多处引用合并，已确认的历史例外不反复建议。区分已核实缺陷、待核验问题和编辑建议，不能把偏好当成错误。依据事实风险、读者影响、修复成本和范围，每周最多挑 3—5 项有价值的问题。

【交付可直接审阅的修改】
每项建议包含文件与具体位置、原文摘录、问题及证据、建议替换的完整片段或最小 diff、影响范围和验证方法。链接修复给出旧链接、已核验的新目标及理由；无法拿准替换内容时列为待核验，不输出猜测补丁。相邻改动保留必要上下文，让用户能判断是否保持原意，不只写“建议更新”或给问题清单。

对文章实质内容的调整，除最小 diff 外，还须展示完整修订稿供确认；未经批准不改仓库。已核实的低风险修复同样先交付建议，不由当前只读任务自动实施。审批、写入与验证遵循共用约定。

Issue 可折叠保存问题标识、来源、审核/修复状态与下次检查范围；只报告相较既有建议的新问题或状态变化，没有有价值发现时返回 no_update。
