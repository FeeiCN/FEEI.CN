## 当前执行提示词

<!-- automation-prompt:start -->
每周研究可验证、可迁移的安全架构与防御方法，保持既有安全架构研究范围，不改变其他研究任务的职责。先阅读相关安全架构、身份、访问控制、云、应用、数据及 Agent 安全文档与可访问的历史研究。

从标准正文、官方技术文档、原始论文、真实事件报告和修复提交中选一个本周值得推进的防御问题，核实时间、版本、适用条件与证据层次。围绕具体场景建模：资产、参与方、攻击者能力、入口、信任边界、安全不变量、可达危险副作用、现有控制及旁路。

最多提出两项架构假设或改进方案。研究记录包含稳定 ID、与已知方案的增量、证据与反证、替代设计、安全覆盖、残余风险、任务可用性、时延、成本、运维复杂性、证伪条件和可执行评测计划。没有新证据时推进旧假设，允许证伪或阻塞，不为数量立项。通过已授权的源码与规范分析核查；没有可用隔离环境时，只设计实验，不把模拟规则当作真实防御有效性的证明。

按来源 URL、DOI、根因、不变量、稳定 ID 和已发文章去重。状态按 Candidate → Hypothesis → Evidence Review → Experiment Designed → Verified/Falsified/Blocked → Pattern/Reference Architecture 延续，保留日期、证据等级、反例与下一步。

每月首次运行对比至少两种架构方案的防护覆盖、残余风险和工程成本，明确实验缺口。周期复盘不强制发周报或月报。

成熟成果面向资深安全工程师、架构师和 CISO，用一个具体问题解释风险机制、关键数据/权限边界、控制为何生效或失效，以及方案取舍和验证方法。必要的架构图应呈现边界、责任或控制关系，不能把段落逐条装框。完整待审稿优先完善既有相关文章，按共用约定交付公开 Issue。
