## 当前执行提示词

<!-- automation-prompt:start -->
读取已授权的真实健康数据，回顾近7天可用体重变化，并为固定壁纸模板准备结构化数据。先读健康数据存储规范；原始数据不在 Git，以 https://feei.cn/data/health/ 日期索引及其声明分片为准。output/personal-data-index.json 是本轮已获取入口，不代表完整测量数据；继续核对必要分片和实际格式。旧月文件仅在核实为旧版原始测量而非缓存时使用，不猜测路径或把缓存当事实。

核对 weight_body_mass 指标、units、实际测量时间；不能误读 lean_body_mass 或 body_mass_index。原始单位 kg 按 1 kg = 2 斤转换，保留精度计算，展示统一为市斤。日期按 Asia/Shanghai 解释，按日去重并采用当日最后有效称量；冲突和明显异常先核实。读取当年真实记录，以及核实既往阶段所需的历史记录；缺测不填零、不插值、不平滑，不把旧记录标为今天。近期无新记录时注明真实截止日期并提醒称量同步；核心记录获取失败返回 blocked，不能生成假数据。

运动使用 apple_exercise_time，核验单位 min，按日核对真实累计值；重复来源不得重复相加，不与 workouts 时长叠加。缺失不等于零，只有明确记录为零才填零；周统计只包含本周一到昨天的已结束、有记录日期，当天未结束不判失败。

【固定输入】
只创建 output/wallpaper-data.json，结构如下（尖括号说明必须替换为真实数据，不可直接照抄）：
{
  "as_of": "<本轮北京时间 YYYY-MM-DD>",
  "weights": [{"date": "<称重日期 YYYY-MM-DD>", "weight_jin": 160.0, "source": "<实际读取的 https://feei.cn/data/health/ 下索引或分片 URL>"}],
  "exercise": [{"date": "<日期 YYYY-MM-DD>", "minutes": 30.0, "source": "<实际读取的健康数据 URL>"}]
}
上面的数字只说明字段类型，禁止当作本人记录。weights 必须有当年有效记录；每个数组同一天只能一条记录。没有可靠运动记录时 exercise 使用空数组，并在交付摘要说明缺失，不伪造计数。每条来源必须能追溯到本轮实际读取的记录。

【固定版式与阶段】
版式由仓库 scripts/render_weight_wallpaper.py 统一维护：iPhone 16 Pro Max 深色锁屏，PNG 1320×2868 与同版 SVG，顶部和底部避开时间、小组件和系统按钮。主标题为下一阶段目标；阶段依次155、150、145、140斤，根据提供的真实历史推进，短期回升不撤销已达成阶段，达到140后保持。历史无法核实时说明口径，不捏造达成记录。副标题显示真实差距；当前体重与日期只展示一次；全年曲线按月份显示、保留缺测间隔；保留长期目标140斤与“今天，完成30分钟运动”，周反馈区分已记录天数与达标天数。不要重新设计布局、创建新的绘图脚本或让模型生成 PNG/SVG，不恢复已删除的饮食标语。

最终 JSON 的 report_markdown 简短说明最新称重日期、阶段差距、近7天真实变化、数据缺失及来源口径。准备好真实输入后返回 completed、artifacts 先置空数组；workflow 在模型退出后调用固定渲染器，成功生成并校验 PNG/SVG 才交付。缺少核心数据返回 blocked。交付步骤将 PNG 作为原生图片嵌入公开 Issue，并通过公开 Release 保留 PNG/SVG 原文件与历史版本，不上传原始健康分片或结构化输入。
