## 当前执行提示词

每天北京时间 07:45 先用固定脚本创建当天 Issue，再执行个人记录线索采集；白天每小时补检查缺失交付，已有记录不重复创建。北京时间 23:15 刷新同一 Issue 的自动数据评论，23:45 与次日 00:15 对缺失或延迟来源补检查；次日补检查仍使用前一天日期。流程分为自动采集线索、本人补充事实、整理成稿、确认写入四阶段；当前无人值守运行只完成自动采集，不虚构本人回答或直接拼成散文。

【自动采集】
以 output/context.md 中固定的 target_date 为准，不因运行跨午夜而切换日期；先读已确认的当天记录和实际可访问的历史，避免重问。客观数据优先读取 output/personal-data-index.json 中已取回的文件，并依健康数据存储规范和 src/components/DailyRecordMeta.tsx 核对实际口径：睡眠评分为 /data/sleep-score/YYYY/MM/DD.json；健康为 /data/health/YYYY/MM/DD.json 日索引及其声明分片；阅读为 /data/reading/YYYY.json、/data/reading/weeks/YYYY.json。只有实际响应证明仍为旧版完整原始数据时，才使用旧月文件，不把月趋势缓存当事实源。

默认查看当日与必要的近 7 天趋势，确有意义才扩大至 30 天。按真实日期、单位、导出时间和覆盖情况核对睡眠、运动、步数、体重、阅读及目标相关的心情或用药记录。零与缺失、没有记录与没有发生必须区分；多来源不重复相加，状态冲突、跳变与同步滞后明确说明，不从缺失推断没服药、没睡觉或心情不好。采集不要求本人截图，读取失败说明实际失败层级和影响。

睡眠评分日期取来源 Issue 创建时间的北京时间日期，和健康日索引按日期关联；读取 provenance、observations 和 quality.warnings。手表关机可能影响评分时保留这一实际限制；“6小时”等 durationPrecision=display_hours 的摘要不能当作精确分钟数，不从关机时间推断醒来时间。不把评分与 Health Auto Export 分期时长混成同一项原始测量。

只读核对 FeeiCN 当天 00:00 至当前实际可访问的 GitHub 活动，优先本仓库；按目的合并真正进展，区分计划、提交、合并、构建与部署，过滤自动同步、重复构建及无关活动，不猜投入时长、情绪或意义。权限受限不以“未查到”推断“没做事”。

筛选与本人当天工作、投资、生活或出行直接相关的重要新闻、特殊日期、历史节点、异常事件和昨日未完事项。优先官方来源核对时间与证据；宁缺毋滥，不为覆盖 AI、安全、金融、杭州、天气等领域逐项凑新闻。普通发布、融资、论文或涨跌不自动进入日记。

【本轮交付】
以“今天发生了哪些真正值得记住的事？”开头，将核实后的信息合并为最多三条有用线索，交付到固定 target_date 的原 Issue 评论，保留早间入口与自动数据快照。不逐指标报表、不生成工作汇报，不默认所有客观数据都值得写入。已知事实供本人补充或纠正，不反复追问；保持一个问题，不追加固定健康、工作、财务、感恩问卷。数据不完整但已有可靠线索时交付这些线索并说明缺口；关键数据完全未读到时返回 blocked，不能把空泛问题当作采集完成。来源与核验限制放在线索之后。

【数据刷新与延迟】
晚间固定脚本刷新当天 Git 提交、Issue 创建/关闭和新增评论、健康日索引中的运动/步数/体重/睡眠、睡眠评分、阅读与各平台 Token 日期数据。数据评论独立于本人叙述，不覆盖本人回复、已确认稿或网站文章；来源失败时保留上次成功快照并标明旧数据，缺失不记作零。各来源保留时间和口径；Token 平台账单日期不擅自换算成北京时间，不把自动提交或机器人评论当作本人工作成果。已发布日记的动态数据随原来源更新，正文内写死数字需提出修订，不能自动重写。GitHub cron 不保证准点，运行摘要记录计划时刻、运行创建、运行开始与实际采集时刻，不把所有时间差都称为排队。

【本人补充后的成稿】
获得事实补充后，由交互流程按我的写作原则、散文写作规范整理最近认可的完整稿。选择最值得留下的一至三件事，有主线就突出主次，没有则允许短记并列。保留人物、动作、对话、场景、真实念头、口语、幽默、不确定和不完美；可以调整讲述顺序、使用恰当修辞和留白，但不歪曲事实先后与因果，不编造感官、心理、人物或意义。外部新闻只有与本人经历确有联系才融入，并区分当时已知和整理时得知。

成稿前完成一至两轮内部编辑，检查事实、主次、过渡、时间地点与因果、重复和空泛升华。新增细节融入合适场景，不总追加文末；实质修改后重新展示完整稿。标题取自真实场景、物件、人物、动作或思考，结尾自然，不强迫总结或升华。默认不附评分和修改报告。

【确认写入】
线索和待确认草稿可公开交付 Issue；网站文章必须等本人确认具体版本。日记文件、日期 slug、published_at、自然标题、location、day_status、icon 和 description 均遵循 SKILL 中既有规则，不另写一套格式。写入流程按共用约定核对最新 main 与当月目录，保留其他日期和已确认正文。
