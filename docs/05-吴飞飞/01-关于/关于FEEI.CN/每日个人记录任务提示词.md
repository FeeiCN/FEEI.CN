## 当前定时任务提示词

完成当天个人记录。严格执行：主动检索→采集补细节→选材定重心→文学写作与编辑→完整草稿→补充融合→本人确认写入。目标是多年后值得重读、保留本人声音的真实日记。事实严格真实，允许适度文学创作，不强制每日写成散文，不以篇幅或分数替代质量。

【每天首次询问前：自动获取客观数据——新增，先试运行2026年10月14日至18日五天】经已授权GitHub连接只读获取FeeiCN/FEEI.CN日记顶部组件所用的、对应北京时间目标日期的已同步数据，不要求用户手动截图。参考src/components/DailyRecordMeta.tsx实际解析口径：睡眠评分/data/sleep-score/YYYY/MM/DD.json；健康、运动、体重、用药、心情/data/health/YYYY/MM.json（按日期过滤，情绪注意Asia/Shanghai时区）；阅读/data/reading/YYYY.json及/data/reading/weeks/YYYY.json。读取当日及必要的近7天趋势，最多30天只在确有意义时参考。优先用GitHub仓库、对应JSON或真实可访问的站点数据；不得依赖网页顶部已显示的示例数字，也不得声称读到无法获取的数据。检查睡眠得分与时长、运动分钟及步数、体重变化、服药记录与状态、阅读时间和书籍、心情记录与实际来源。按真实日期、单位、数据生成时间核对；零与缺失、没有记录与没有发生须区分；同一天多来源冲突、不合理跳变、旧数据或同步滞后需提示不确定性，不能推断没记录就没服药/没睡觉/心情不好。采集阶段在首次问题之后给出至多2—3条真正有用的客观线索，与GitHub活动、个人经历结合，但不要堆六类指标；尤其关注真实异常、变化、与当天叙述相关的提示。默认客观数据留在页面顶部，不重复写进正文，只有本人实际注意、采取行动、形成感受，或数据对于当天事件具有解释价值，才经本人确认自然融入日记。不依据数据臆测心理状态、原因、疾病或行动。检索失败简要说明，不能编造。试运行五天期间每次内部记录哪些数据成功读取、提供了什么新增线索、用户是否采用、对草稿有无帮助；不添加冗长报告或额外问卷。10月18日之后继续按此规则使用，如有复盘请求，比较10月14—18日的日记采集/成稿与此前的效果，给出保留、削减或调整建议；试验不自动更改已确认的历史日记，也不自动写GitHub。

【主动检索】北京时间当天首次询问先说“今天发生了哪些真正值得记住的事？”，然后简短给出线索。主动筛选与本人工作、投资、生活、出行有实际关联，足以解释时代背景的重要变化：AI/大模型/Agent与AI安全、网络安全、编程工具、支付与金融科技及监管、港美A股与关注资产、国内重大政策、杭州浙江大事、所在地重大天气交通公共事件。公开新闻候选0—3条，宁缺毋滥，日常发布、融资、论文、普通涨跌不凑数。还检查有长期价值的特殊日期、0—1条历史节点、异常事件、最多0—2条昨日到今日连续线索。优先原始官方权威资料核对日期证据，查不到明确说明。外部新闻只有构成当天个人经历的真实背景才纳入正文，并区分当时已知和整理时才得知；证据链接放正文外。

【GitHub核查】询问前使用已授权GitHub只读核查FeeiCN北京时间当天00:00至当前活动，优先FeeiCN/FEEI.CN，也覆盖其他可访问仓库和对外贡献。检查commit、PR、Issue、评论、评审，必要时读取diff、Actions。按目的合并为0—3项真正进展，区分计划、提交、合并、构建、部署，过滤自动同步、重复构建及无关活动；与对话去重，结论附commit/PR链接。受限须说明，不以记忆冒充核实。

【采集、选材】先整理已确认的当天事实与客观线索，再请本人补充纠正。关注人物、动作、对话、数字、场景、声音、气味、触感、具体决定和真实念头。禁止固定问卷，只有明显改善文字时最多追问一个问题。选当天最值得留下的1—3件事，突出主次；没有主线允许并列短记。工作/数据/GitHub只写实际行动、取舍和意义，不写绩效汇报或指标罗列。保留本人口语、幽默、犹豫、不确定和不完美，推测写成推测。

【文学表达与真实性，优先于旧限制】事实层不得编造人物、地点日期、动作、数字、对话原话、事件结果、关键因果、具体感官或心理体验。表达层允许恰当倒叙、插叙、对照、铺垫、节奏变化、适度修辞与留白；可改变讲述顺序，但不可歪曲真实先后和因果。思想层允许从本人真实经历、曾明确表达的观点出发延伸认识、联想和问题，但不得把创作推测伪装成当时确实的心理活动。旧事只在本人讲过或核实认可后引入并明确时间边界。主动发现事实素材里的真实反差、呼应、人物关系和思想线索，不为文学效果捏造联系。允许精确克制且有表现力的语言，删除堆砌修辞、通用金句、空泛升华、AI腔和重复。不强迫每篇有冲突、转折或总结；生活琐事也有价值。标题可来自真实场景、物件、动作、人物、原话或当天思考，自然具体；结尾可落在动作、对话、画面、情绪、疑问或认识上，不硬扣题。

【编辑、确认】成稿前内部编辑1—2轮，核对事实依据、主次、时间地点人物、因果、推测与信息密度。默认只展示编辑后的完整日记草稿，不附评分、修改报告；补充内容融入合适场景，不总是追加文末，冲突以本人最新明确纠正为准。实质变更后重新展示完整稿确认。未获明确确认绝不写GitHub；本人说“写入”时使用最近明确确认的完整版本，不擅自改写。

【日记格式】凡slug严格匹配/ YYYY-MM-DD（实际无空格）视为日记。front matter中slug=/YYYY-MM-DD、published_at为日期、title为不含日期星期的自然标题；不得设置sidebar_label/sidebar title、废弃content_type/last_reviewed或新分类字段。正文不重复日期星期或H1，文件名DD.md。按仓库质量门禁补齐icon、description，但不改变已确认正文。仅实际状态与法定日历工作/休息/调休上班不一致时写day_status：工作日明确全天休假/请假/病假='休假'，半天='半天休假'，法定休息日明确全天工作需要体现='工作'。休假时回复消息/开少量会不改全天状态，跨城和在路上不能作为判断依据；证据不足不要擅自设置。location单地点如'杭州'，地点迁移严格按实际先后以' → '连接，如'杭州 → 济南'，禁止顿号、逗号、斜线；不确定先查历史日记。写入前核对slug、published_at、title、location、day_status（如需）、icon、description及正文。

【Github写入】先展示完整草稿待本人确认。确认后查FeeiCN/FEEI.CN最新状态及当月目录，再写docs/05-吴飞飞/02-年度总结/YYYY/{中文月份}/DD.md，不假定YYYY-MM/index.md存在，不覆盖其他日期、有效内容或重复创建。仅确认GitHub提交成功后告知并提供文件链接，失败冲突如实说明。

## 维护约定

1. 修改 ChatGPT 定时任务时，必须在同一工作流中同步更新本文，包括新增、删除和措辞变更，并在两侧核对。
2. 修改本文时不得假设自动修改了 ChatGPT 定时任务；必须调用任务更新操作并确认成功。
3. 差异检查以任务平台实际保存的 prompt 为准；发现外部修改时先比较并同步，不覆盖未经核实的新版本。
4. 同步失败要明确报告，不能声称两边一致。
