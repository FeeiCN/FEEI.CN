执行器先校验任务 ID、提示词与启用状态，再运行模型，核对结构化结果和真实交付文件。`completed` 表示本次任务产物满足要求，`no_update` 表示已检查但没有实质更新，`blocked` 表示缺少核心数据、能力或权限。workflow 触发、job 成功和任务成果达标是不同状态。

各任务使用独立 `AUTOMATION_*` 仓库变量，可分别暂停；提示词读取与结果验证由 `scripts/automation_tasks.py` 完成。运行结果包含提示词摘要、执行 commit 与来源记录。研究文章仍须确认具体版本后才能写入，定时启用不等于自动发布。

## 执行配置

模型连接沿用仓库 Secrets：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。不在文档或日志中保存凭证。任务执行时不提供 GitHub 写入令牌；模型完成后由固定交付步骤创建审阅 Issue，不自动改文章。

私人任务还需要仓库变量 `AUTOMATION_PRIVATE_REPOSITORY`（`owner/repo`）和 Secret `AUTOMATION_PRIVATE_TOKEN`，令牌须能访问指定私有仓库并创建 Issue；壁纸文件通过该私有仓库的 Release 附件交付，还需 Contents 写入权限。执行器会先核验目标仓库确为私有，再读取个人数据。公开仓库的 Issue、运行附件和日志都不能作为私人交付渠道；未配置时运行失败并明确显示受阻，不生成虚假健康分析或日记。

每项任务的 `AUTOMATION_*` 变量设为 `true` 后允许执行。手动运行与定时运行读取同一份文档提示词、使用相同权限；验证不能仅检查 workflow 是否触发，还应打开对应运行及成果，核对来源、数据日期、交付正文和实际附件。
