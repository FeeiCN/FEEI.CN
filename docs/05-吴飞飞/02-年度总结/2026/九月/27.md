title: 日记和照片，不必一起完成
description: 看见团子老了，想清楚日记和游记的关系，也让照片上传与文字写作通过日期关联，不必在同一天完成。

早上起来，脚和昨天差不多，能走了，但还没完全恢复。喉咙又出了问题，起初像刀片嗓，刷完牙后，变成了明显的异物感。我猜可能是发炎了。

早上和中午都没吃东西。下午好了一点，点了豆大师的江西炒粉和油条。

今天早上还想到，晚上写日记容易忘掉白天发生的细节。今天怕忘记脚和喉咙的变化，临时在备忘录里记了几句。以后也许可以把 DingTalk Pro 一直开着，把当天的声音记录下来，晚上写日记时再回看。录音和备忘录都只是素材，不直接等于日记；它们像一张底片，帮我找回当天发生过什么、当时是什么感觉，最后还是由我筛选、核对，再整理成自己的文字。这样既不会只剩下晚上的模糊印象，也不会把一天变成流水账。

今天看团子，眼神呆滞，行动也迟缓了，已经有点老态龙钟，和湛湛很不一样。它天天被其他猫欺负，看起来有点生无可恋。其他猫倒是一副百无聊赖的样子。

今天把日记和游记的关系想清楚了。旅行中的事情既然已经写进每天的日记，就没必要回来后再单独写一遍游记。同一次旅行的几篇日记连起来，就是完整的旅行记录。以后补充某件事，也只改那一天，不用惦记另一篇是不是也要更新。

“探索世界”也可以由这些日子组成。日记按时间读，足迹按地点看，用的是同一份记录。甚至不必以离开杭州为界，像昨天去南湖露营，虽然没出杭州，也可以算进去。

昨天还在想，怎么才能方便地把照片放进博客，今天找到了一个很满意的解法：日记照常写，照片单独上传，两边通过日期关联。

平时照常拍照、录视频，挑出可以公开的照片，在手机相册里点一下收藏，再用手机上的 FTP 工具上传到服务器对应的年月目录。不用换一套相册，也不用另外建一个文件管理系统。我要做的，就是挑好哪些照片愿意公开。

服务器上的程序监控文件变化，先读取拍摄时间，再把照片转换、压缩成 WebP，去掉 EXIF 等元数据，生成按日期分组的月度索引。打开日记时，页面根据那篇日记的日期去索引里找，有照片就展示，没有就不显示。图片的宽高也记在索引里，横图、竖图按各自比例排好，不必逐张调整。

最方便的是，写日记和整理照片不用互相等。文字先写好了就先发，照片过几天再挑；照片先上传了，日记也可以以后补。只要日期对应，再打开那一天，它们就能出现在一起。补几张照片，不用再去文章里粘贴链接，也不用重新发布网站。

文字继续留在 Git 里，照片放在服务器上，仓库不会因为不断上传照片而越撑越大。以后想换相册的排版，只改展示组件，不用翻出以前的日记逐篇修改。即使图片暂时读不到，文字也照常可以看。

这套设计让我很满意。拍照、挑选、上传和写作可以分开做，不必为了发一篇日记，把所有事情都挤在当天完成。昨天南湖的照片，今天补上就行。
